# Programs Feature

User-created multi-day training programs, stored locally with no account requirement.

- `ProgramsScreen.tsx`: create, edit, multi-add from RepDB, save, confirm deletion, and start a workout. No sample plans are seeded. Unsaved edits are retained on ordinary tab switches; use Save program before reloading or closing the app.
- `starterPrograms.ts` / `StarterProgramLibrary.tsx`: bundled PPL, Upper/Lower and FBEOD templates with day-by-day previews and moderate working sets. Use creates a fresh unsaved draft with catalog-resolved names and unique day/exercise IDs. Save creates an editable copy OFF; activation remains explicit. PPL has Sunday rest; Upper/Lower has Wednesday/weekend rest; FBEOD alternates training/rest in a rolling 4-day cycle (3–4 workouts/week). No load assumptions or completed sessions are generated. Tests verify catalog IDs, direct-muscle frequency/volume, independent copies, automatic rest protection, and missed-workout streak gaps in both storage backends.
- `ProgramExerciseList.tsx`: numeric targets, removal, drag handles with edge auto-scroll, and accessible move-up/down actions. Each occurrence of a lift has its own ID and targets.
- `ProgramScheduleEditor.tsx`: weekly Monday–Sunday schedules or 1–28-day repeating cycles, a local start/anchor date, per-day names, Training/Rest choices only, and confirmation before truncating training days or days with exercises/names. New days default to Rest. Each training day has independent exercises and goals. Switching a day to Rest retains its exercises for switching back, but never schedules those exercises on that day.
- `programModel.ts`: typed per-set targets (`reps`, `repRange`, or `duration`), validation, limits (1–12 sets, 1–100 reps, 1–3600 seconds, 100 exercises per day), pure reorder geometry, DST-safe civil-date scheduling, schedule revisions, and immutable day-specific workout snapshots. Only the current multi-day format is supported; current exact-rep fields upgrade on read without restoring obsolete unset days.
- `ExerciseTargetEditor.tsx`: separate Reps, Rep range, and Timed selectors. Reps has one rep goal; Rep range has independently editable minimum/maximum goals and rejects reversed ranges. Rep goals, range bounds, minutes, and seconds all have bounded +/− buttons and editable numbers. Controls wrap into full-width rows on narrow phones. Durations are stored as integer seconds per set. The workout logger shares the time steppers, shows the prescription separately, and saves actual reps or duration; it does not infer completion or run a countdown timer. Values apply uniformly to all sets in an entry.
- Timed results use `durationSeconds` on web and `set_entries.duration_seconds` on native, with zero reps. They contribute completed sets, timed-work totals, and streaks, but never estimated 1RM, average lifted weight, or rep-based volume. Mixed sessions retain their strength metrics from rep-based work only.
- `storage/programsRepository.ts`: native SQLite / web AsyncStorage persistence, serialized writes, and corruption/error handling.
- Program workouts preserve their own snapshot and link logged results to individual planned entries. Starting a program never fabricates completed sets or replaces an active session.

## Schedule and streak rules

- Saving a program does not activate it. **Turn program on/off** appears near the top of every saved program card and requires confirmation. Only one program can be on; turning another on replaces it. The regular **Start Session** button loads the current weekday/cycle day's exercises from the active program. Workouts can still be started from any training day explicitly without changing the active program.
- Rest protection begins on the later of activation and the schedule's start date. Cycles advance by calendar date, not by completed workouts; missed training days do not shift the cycle. Weekly plans always use the chosen weekdays.
- Scheduled rest days count toward consistency, including days when the app was closed. Future rest days never count early. Missed training days are not automatic rest days; manual rest marking remains available.
- Editing, switching, stopping, or deleting an active program applies from today, preserving earlier schedule revisions. Today's classification may change; manual rest and completed workouts always remain. Saved workout snapshots are independent of later edits.
- Native SQLite v7 and web library v3 commit programs and schedule history atomically. The user-requested prelaunch reset applies only below native version 6 / before the web version-6 marker. The 6→7 migration adds nullable duration storage transactionally and preserves current training data. Authentication and profiles are not reset. Corrupt current data is reported, never silently replaced.
- Session refreshes schedule/streak on focus, app resume, and date rollover, and offers today's training day or recovery status. Programs and schedules are device-local; no account or network is required.
- Automatic starts resolve the program/date from storage at creation time. Rest days, a future start date, or no active program yield an unplanned session. An unfinished workout is resumed intact across date changes, program switches, or turning a program off. Loading a plan never creates completed sets; tapping each planned exercise opens the logger for actual results.
- The streak card's muted `(x active / x rest)` subtitle counts distinct days within the current streak, not all-time totals. Completed workouts take precedence over same-day rest, and future/invalid dates are excluded. Active plus rest counts always equal the current streak.

## Import prototype

**Programs → Import program** accepts pasted text and PNG/JPG/WebP screenshots. No videos, URL fetching, completed workout imports, or LLM are included. This is local OCR plus a deterministic parser, not an autonomous AI agent.

- `ProgramImportScreen.tsx`: editable source, sequential screenshot additions, OCR progress/cancel/error handling, line-by-line review, manual library matching with visible filters, sets/target corrections and line removal. Sources/images stay in component memory, not the saved program. Reloading discards unsaved imports; ordinary tab switches preserve them.
- `importProgram.ts`: weekdays or numbered Day sections, explicit rest headings, exact reps, ranges, timed targets, header-aware tables, dated workout logs, and normalized unique RepDB name matching (including safe lift-name plurals and Tbar/T-Bar). Uncertain names remain unresolved; absent/unsupported numbers remain invalid, never filled with invented training targets. Repeated headings and unsupported notes are flagged with source lines. Supersets, per-side goals, tempo, AMRAP, and different timed goals per set require manual edits.
- Limits: 30,000 characters, 400 lines, 200 exercises total/100 per day; screenshots up to 15 MB and 24 MP. English, clear single-column screenshots work best. OCR can confuse names, numbers, columns and day headings; reviewing every line is mandatory.
- A single workout proposes a 1-day cycle with a warning; missing weekly/cycle days are proposed as Rest and listed explicitly. The user must check matches/targets/warnings, then review the name, repeat schedule, start date and every Training/Rest day in the existing builder. A second schedule confirmation gates **Save program**. New IDs are generated at handoff. No schedule is activated and no workout/streak records are created by importing or saving.
- `importOcr.web.ts`: Tesseract.js 7, using a browser worker with English data. First use downloads versioned reading assets from jsDelivr (worker/core v7, English model 4.0.0_best_int); images are never uploaded. Model caching is best-effort, so network access may be needed again. Abort/90-second timeout ignore late results and terminate the worker when available.
- `importOcr.ts` + `modules/orca-ocr`: optional local Expo module, Apple Vision on iOS and bundled Latin ML Kit on Android. Missing native support produces an actionable fallback, not an app crash. Expo Go supports pasted text only; browser screenshot OCR works without rebuilding. Native screenshot OCR needs a new development/production build. The native bridge uses current Expo module/Gradle APIs; no incompatible third-party Expo OCR wrapper is installed. A cancelled native recognition may finish in the background, but its result is ignored.

Native setup: install dependencies, then use `npx expo run:ios` (full Xcode required) or `npx expo run:android` (Android SDK required). Local modules autolink from `modules/`. Run device smoke tests with a clear screenshot, a blank image, cancellation and retry, airplane mode, and app resume. Autolinking/JS exports are checked here; native compilation and physical-device OCR still need verification.

Parser/OCR-boundary tests live in `tests/program-import.test.mjs`. Repository tests verify that saving imports leaves the existing active program, session and streak history unchanged on web and SQLite. `tests/fixtures/import-screenshot.svg` is a deterministic OCR fixture (rasterize it to PNG for the file picker); it is not a seeded training plan.

### Import reliability fixes

- Numeric titles before day/table headings (for example, “4 Week Strength Plan”) are program names, not phantom exercises. Adjacent OCR name/prescription lines are joined with both original lines retained and a pairing warning.
- Pipe/tab/multi-space tables honor Exercise/Sets/Reps-Time headers even when reordered. Extra Rest/Tempo columns are flagged as not saved; blank cells never shift the remaining values. Numeric Time/Duration cells without units remain invalid rather than becoming reps. Standalone rest-between-set instructions are review notes, not exercises.
- Review shows live blocking issues before continuation. After removing the last exercise in a training day, the user can explicitly mark that empty day Rest without discarding other corrections. Editing a match/target clears the acknowledgment.
- Source edits invalidate the previous review until it is rebuilt. Returning to a review without changing source preserves its corrections. Oversized pasted text is rejected with an explanation instead of silently truncated. Screenshot cancellation immediately releases the input and retry controls; late picker/OCR results cannot alter a cancelled or newer request. Dismissed pickers clear their loading message, loading stages show progress, and browser image URLs are released on replacement/cancellation/unmount.

### Workout-log tables

- The browser now requests word coordinates as well as text. `importOcrLayout.ts` reconstructs dated, headerless logs with three aligned numeric columns into editable `Date | Exercise | Reps | Weight | Sets | Notes` rows. Blank cells, bodyweight labels and notes retain their columns. The expected column interpretation is displayed explicitly for user review; this is a heuristic for that layout, not arbitrary spreadsheet understanding. Existing labeled tables keep their own headers/order.
- A second segmentation pass runs only for detected log tables. It can recover a dropped decimal only when the digits and word coordinates agree; both readings are disclosed in the warnings. It does not replace unrelated words/numbers or infer missing values. Undetected layouts retain ordinary OCR text. No image uploads, new model dependencies, storage migrations or account requirements are introduced.
- Dated text is detected automatically; undated pasted logs can opt into **Read as workout log table**. Pipe/tab headers may reorder columns; headerless rows use the displayed Reps / Weight / Sets convention. Blank exercise cells sum set counts only within the current session/preceding exercise. A new named row remains a separate exercise occurrence. Invalid or orphan rows are reported, never turned into fake lifts.
- Fractional reps can round to the nearest whole rep (6.5 → 7), with original values and rounding notes retained in review. Different logged reps propose a min–max program target; inconsistent outliers that might be a lost decimal are blocked for correction. Unlabeled cardio values require explicit duration/units and set-count confirmation instead of interpreting speed/incline as weights/sets.
- Each dated session becomes a labeled training-day draft. Dates never backdate the program, infer a weekly cadence/rest gaps, or create workout history. The user chooses the repeat schedule and rest days in the builder. Weights and freeform notes are visible in review but not persisted in the program schema. Changing rounding/log settings invalidates an old review just like editing source text.
- Table word-coordinate reconstruction is currently **web-only**; native OCR remains the existing text reader. The shared log parser and rounding review work on all platforms with structured pasted text. Native table geometry needs separate bridge/device work.
- `scripts/checkImportScreenshot.mjs /absolute/path/to/image.png [cache-directory]` runs the same two-pass OCR/layout/parser locally with Node 24 for reproducible smoke tests. It downloads public English OCR assets on first use, never uploads the image or writes a program. Tests use synthetic log/geometry data; the user's original screenshot is not copied into the repository.
